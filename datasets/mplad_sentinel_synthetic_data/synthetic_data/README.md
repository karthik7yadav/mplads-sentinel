# MPLAD Sentinel — Synthetic Application/Demo Data Layer

**This is synthetic demo/application data. It is not production-ready and
is not official government data.**

## What this package is

An application/workflow data layer that sits **above** the frozen:

```
Stage 1.6 Canonical Data Foundation
  -> Stage 2.1.1 Risk Engine
  -> Stage 2.2.1 Decision Intelligence
  -> SYNTHETIC APPLICATION/WORKFLOW DATA   <-- this package
```

It demonstrates the MP team workflow, DM/DA investigation workflow, MoSPI
monitoring, evidence handling, and feedback loop described in the MPLAD
Sentinel solution ("VikasNetra", SIH26102) — **without** touching, retraining,
reweighting, rethresholding, or otherwise modifying the real Stage 2.1.1
risk engine or Stage 2.2.1 decision intelligence outputs.

## How to reproduce

```bash
python3 generate_synthetic_data.py      # deterministic, seed 20260907 — writes synthetic_data/*.csv + .yaml
python3 validate_synthetic_data.py      # 65 checks — writes SYNTHETIC_DATA_VALIDATION.md, exits non-zero on any FAIL
```

Both scripts are pure (no wall-clock or OS-entropy randomness). Running
either twice produces identical output — verified via `diff -rq` on the
full generated directory and SHA-256 on the validation report.

## Critical integrity guarantees (all independently verified)

- Every Work ID referenced anywhere in this package exists in the
  authoritative `decision_intelligence.csv` — none invented.
- `overall_risk`, `risk_band`, `lifecycle_mode`, `primary_risk_component`,
  `primary_reason_title`, and financial fields are copied **exactly** —
  never recalculated, reworded, or reweighted.
- Linked citizen requests carry state/constituency that **exactly** matches
  their linked real Work — including the two edge-case Work IDs
  (`WS/MP446/2023-2024/122215`, `WS/MP18019/2025-2026/216372`) that
  themselves have blank state/constituency in the real data.
- Every `RECOMMENDATION_CREATED` / `RECOMMENDATION_SUBMITTED` citizen
  request has a corresponding recommendation record.
- All spatial data is 100% synthetic coordinates, explicitly labeled
  `"SIMULATED / SYNTHETIC DEMONSTRATION CONTEXT"` — never presented as a
  real measured GIS distance.
- Vendor reference data explicitly states it is not an official blacklist
  and does not affect the risk score, risk band, or risk engine output.
- Investigation outcomes are explicitly demonstration outcomes, never
  presented as actual government findings.
- Feedback is meaningful narrative text (not generic boilerplate) and is
  framed as future training/evaluation input only — no automatic
  retraining is implied or performed.

## Known, documented limitations (not defects — real-data constraints)

See `SYNTHETIC_INTEGRATION_MANIFEST.yaml` → `limitations` for the full
list, in particular:
- `PRE_SANCTION` has no LOW or CRITICAL risk-band rows anywhere in the real
  72,675-row dataset.
- ~31% of all real rows have blank state/constituency/category; the demo
  registry deliberately includes two such rows as edge cases rather than
  hiding the gap.
- No real MPLADS GIS coordinates exist anywhere in the source data — the
  spatial demo layer is necessarily 100% synthetic.
- No official planned/expected completion date exists in the source — no
  "delay" is ever computed, real or synthetic.

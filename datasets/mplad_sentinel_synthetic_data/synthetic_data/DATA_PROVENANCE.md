# DATA_PROVENANCE.md

MPLAD Sentinel — Synthetic Application/Demo Data Layer — Provenance Statement

## Architectural position

```
Stage 1.6 Canonical Data Foundation        (frozen, real MPLADS-derived)
  -> Stage 2.1.1 Risk Engine                (frozen, real, unmodified)
  -> Stage 2.2.1 Decision Intelligence      (frozen, real, unmodified)
  -> SYNTHETIC APPLICATION/WORKFLOW DATA    (this package — new, synthetic)
```

This package is an **application/demo data layer**. It does not retrain,
reweight, rethreshold, or otherwise modify the Stage 2.1.1 Risk Engine or
the Stage 2.2.1 Decision Intelligence outputs. Every real field it uses is
copied verbatim from `decision_intelligence.csv` and cross-checked by
`validate_synthetic_data.py`.

## REAL (REAL_MPLADS) — sourced from Stage 2.2.1 `decision_intelligence.csv`

Present only in `demo_work_registry.csv` (14 rows) and, by reference, in
`synthetic_investigation_cases.csv`'s `risk_score` / `risk_band` /
`lifecycle_stage` / `primary_risk_reason` columns:

- `work_id`
- `state`, `constituency`, `work_category`
- `lifecycle_mode`
- `overall_risk`, `risk_band`
- `primary_risk_component`, `secondary_risk_component`
- `primary_reason_title`
- `recommended_amount`, `sanctioned_amount`, `total_expenditure`

None of these values are ever recalculated, reworded, or reweighted by this
package. Validation checks 3–8 and 19–21 in `SYNTHETIC_DATA_VALIDATION.md`
confirm byte-for-byte equality against the authoritative source for every
row that carries them.

## SYNTHETIC (SYNTHETIC_DEMO) — generated by this package, not official data

- `synthetic_users.csv` — fictional MP_TEAM / DM_DA / MOSPI_ADMIN accounts.
- `synthetic_citizen_requests.csv` — fictional citizen need submissions.
- `synthetic_work_recommendations.csv` — fictional MP-team recommendation drafts.
- `synthetic_asset_registry.csv` — fictional public assets with synthetic coordinates.
- `synthetic_spatial_scenarios.csv` — synthetic reference/asset coordinate pairs and simulated distances. Explicitly labeled `"SIMULATED / SYNTHETIC DEMONSTRATION CONTEXT"` — never presented as real GIS measurement.
- `synthetic_vendor_reference.csv` — fictional vendor entries, explicitly not an official blacklist, does not affect risk output.
- `synthetic_investigation_cases.csv` — *workflow* fields only (`workflow_stage`, `assigned_to`, `created_at`, `status`); the risk fields on the same rows are REAL_MPLADS (see above).
- `synthetic_investigation_evidence.csv` — metadata-only evidence records; no fabricated official documents.
- `synthetic_investigation_outcomes.csv` — demonstration outcomes only, never presented as actual government findings.
- `synthetic_feedback.csv` — synthetic narrative feedback, stored as a potential future training/evaluation dataset — no automatic retraining implied or performed.
- `demo_scenarios.yaml` — narrative scenario scripts referencing the IDs above, each scenario explicitly tagged with its data origin.

## What this package never claims

- It never presents synthetic figures as official MPLADS records.
- It never claims a synthetic spatial distance is an actual measured GIS distance.
- It never claims the synthetic vendor list is an official blacklist.
- It never claims investigation outcomes are actual government findings.
- It never claims or implies that feedback automatically retrains the (frozen) risk engine.
- It never describes itself as "production-ready" — it is synthetic demo/application data only.

## Reproducibility

`generate_synthetic_data.py` uses a single fixed seed (`RANDOM_SEED = 20260907`)
and a fixed reference date (`2026-09-07`) — no wall-clock or OS-entropy
randomness anywhere. Running the generator twice produces byte-identical
output (verified via `diff -rq` across the full output directory).
`validate_synthetic_data.py` is a pure read/compare script with no
randomness and produces an identical report on repeated runs (verified via
SHA-256 of the report file across two runs).
